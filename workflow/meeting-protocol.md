# 会议流程协议

## 阶段概览

```
┌─────────┐
│ 议题输入 │
└────┬────┘
     ▼
┌─────────────┐
│  唐·诺曼     │  定义做什么、为什么
└──────┬──────┘
       ▼
┌─────────────┐
│ 马丁·福勒    │  设计怎么做、系统结构
└──────┬──────┘
       ▼
┌─────────────┐
│ 林纳斯·托瓦兹 │  评估能不能做、多久做完
└──────┬──────┘
       ▼
┌─────────────┐
│ 布鲁斯·施奈尔 │  审查安全与合规
└──────┬──────┘
       ▼
┌─────────────┐
│  交叉讨论    │  针对分歧点辩论（可选）
└──────┬──────┘
       ▼
┌─────────────┐
│ 维尔纳·沃格尔 │  审阅 → 通过 / 否决
└──────┬──────┘
       ▼
   结论输出
```

## 议题输入要求

提交议题时需包含：

- **背景**：为什么现在要讨论这个问题
- **目标**：期望达成什么决策或产出
- **约束**：预算、时间、人力、合规等硬性限制
- **已知信息**：已有调研、原型、竞品参考等

## 各阶段规则

### 1. 顺序发言

默认按 唐·诺曼 → 马丁·福勒 → 林纳斯 → 施奈尔 顺序 invoke 对应 Skill。后发言的专家应：

- 承接前者的输出，标注同意或分歧
- 不重复已达成共识的内容
- 新增本领域视角的信息

### 2. 交叉讨论（可选）

当存在以下情况时，进入交叉讨论：

- 两位及以上专家意见冲突
- 施奈尔提出 Blocker 但林纳斯认为成本过高
- 架构方案与产品 MVP 范围不匹配

交叉讨论规则：

- 只讨论有分歧的点，不重新走全流程
- 每位相关专家最多一轮补充发言
- 仍无法达成一致时，提交维尔纳·沃格尔裁决

### 3. 技术总监审阅

维尔纳·沃格尔（`werner-vogels`）阅读全部发言后，输出「通过」或「否决」。

**否决后**：按 [roles/cto.md](../roles/cto.md) 中的否决流程，指定退回环节修改，修改完成后重新提交审阅（不必重走无关环节）。

## 结论输出

通过后，最终文档应包含：

1. 议题与背景
2. 五位专家的核心意见摘要
3. 技术总监的最终结论与行动项
4. 风险登记与跟进项
